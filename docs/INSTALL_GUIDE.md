# VP App 설치 및 네트워크 구성 가이드

이 문서는 현장에서 VP App을 설치하고 네트워크·모니터·오디오·멀티 PC 동기를 구성하는 설치 기사와 시스템 통합 담당자를 위한 안내서입니다. 일상 운영(파일 추가, 재생목록 편집, 재생 제어)은 [운영자 사용 설명서](USER_GUIDE.md)를, 외부 제어기(AMX 등) 연동은 [AMX/TCP 연동 매뉴얼](TCP_PROTOCOL.md)을 참고하십시오.

## 1. 시스템 요구 사항

| 항목 | 요구 사항 |
|------|-----------|
| 운영체제 | Windows 10 / Windows 11 (64비트, x64) |
| 설치 권한 | 설치·제거 시 관리자 권한 필요. 설치 후 실행은 일반 사용자 권한으로 동작 |
| 그래픽 | Direct3D 11 지원 GPU 권장. 하드웨어 가속은 지원 시 자동 사용되며, 미지원 시 소프트웨어 처리로 자동 전환됩니다 |
| 웹 브라우저 | 제어 화면(웹 UI)에 접속할 최신 브라우저 (같은 PC 또는 네트워크상의 다른 기기) |
| 네트워크 | 원격 제어·멀티 PC 동기·라이브 입력을 사용할 경우 유선 LAN 권장 |

참고 사항:

- 하드웨어 가속 지원 여부는 **설정 › 재생 › 하드웨어 가속**에서 `지원됨 (GPU 가속)` 또는 `미지원 (소프트웨어 처리)`로 확인할 수 있습니다. 별도 토글은 없습니다.
- 여러 창에 대해 다음 트랙을 미리 로드(프리롤)하므로, 창 수와 콘텐츠 해상도에 비례해 메모리를 사용합니다. 현재 메모리 상태는 **설정 › 시스템 › 메모리**에서 확인합니다. 프리롤 범위는 **설정 › 재생 › 전 트랙 프리롤**의 `룩어헤드 (창당 미리 로드)`, `최대 프리롤 덱 (전역 상한)`으로 조정합니다.
- NDI 입력을 사용하려면 PC에 NDI 런타임(NDI 5 또는 6)이 별도로 설치되어 있어야 합니다.
- ASIO 출력을 사용하려면 해당 오디오 인터페이스 제조사의 ASIO 드라이버가 설치되어 있어야 합니다.

## 2. 설치, 업그레이드, 제거

### 2.1 설치

1. 설치 파일 `VP-App-Setup-<버전>.exe`를 관리자 권한으로 실행합니다. 설치 언어는 한국어/영어 중 선택합니다.
2. 설치 폴더를 지정합니다. 기본값은 `C:\Program Files\VP App`입니다.
3. **추가 작업 선택** 단계에서 다음 두 항목을 확인합니다.

| 작업 | 설명 |
|------|------|
| Windows 시작 시 자동 실행 (관리자 권한 불필요) | 설치한 사용자 계정의 로그온 시 VP App이 자동 실행되도록 등록합니다 (HKCU Run 키). |
| 방화벽에서 제어/동기 포트 허용 | 아래 [4.2 설치기가 등록하는 방화벽 규칙](#42-설치기가-등록하는-방화벽-규칙)을 등록합니다. 원격 제어나 멀티 PC 동기를 사용하는 경우 반드시 선택합니다. |

4. 설치가 끝나면 `지금 VP App 실행`을 선택해 바로 실행할 수 있습니다.

설치기가 수행하는 작업:

- 설치 폴더에 프로그램 파일 복사 (서버 실행 파일 `VPApp.exe`, 웹 UI, 재생 엔진 `player\`, 서드파티 라이선스 고지 등)
- 설치 폴더에 **Users 그룹 수정 권한** 부여 (재설치 없이 웹에서 업데이트하기 위해 필요)
- 시작 메뉴: `VP App`, `VP App 제거`, `라이센스 고지 (Third-Party Licenses)`
- 공용 바탕 화면에 `VP App` 바로 가기
- 선택 시 방화벽 규칙, 자동 실행 등록

VP App은 콘솔 창 없이 백그라운드로 실행되며, 바로 가기와 자동 실행은 모두 설치 폴더의 `vpapp-launch.vbs` 런처를 통해 실행됩니다.

### 2.2 첫 접속

VP App이 실행되면 웹 서버가 포트 3000에서 대기합니다.

- 같은 PC: `http://localhost:3000`
- 다른 PC/태블릿: `http://<VP App PC의 IP 주소>:3000` (방화벽 허용 필요)

### 2.3 업그레이드 (설치 파일로 재설치)

- 새 버전 설치 파일을 같은 방식으로 실행하면 기존 설치를 덮어씁니다. 실행 중인 `VPApp.exe`, `vplayer.exe`는 설치기가 자동으로 종료합니다.
- 설정, 재생목록, 미디어 파일은 사용자 데이터 폴더에 있으므로 업그레이드 후에도 유지됩니다.
- 설치 파일 없이 웹 UI에서 업데이트하는 방법은 [10. 소프트웨어 업데이트](#10-소프트웨어-업데이트)를 참고하십시오.

### 2.4 제거

**제어판 › 프로그램 제거** 또는 시작 메뉴의 `VP App 제거`를 실행합니다. 제거 시:

- 설치 폴더 전체가 삭제됩니다 (웹 업데이트로 추가된 파일 포함).
- 설치기가 등록한 방화벽 규칙(이름이 `VP App`으로 시작하는 9개 규칙)이 삭제됩니다.
- 자동 실행 등록(HKCU Run 값 `VP App`)이 삭제됩니다. 단, 제거를 실행하는 계정의 레지스트리에서만 삭제되므로, 다른 계정으로 제거한 경우 해당 사용자 계정에서 앱의 자동 실행을 끄거나 값을 직접 삭제하십시오.
- 구버전이 만든 작업 스케줄러 항목 `VP App`이 있으면 함께 삭제됩니다.
- **사용자 데이터는 삭제되지 않습니다.** 설정·DB(`%APPDATA%\db`), 로그(`%APPDATA%\vp_app2`), 미디어(`%USERPROFILE%\media`)는 남아 있으므로, 완전 초기화가 필요하면 수동으로 삭제합니다.

## 3. 설치 경로와 데이터 위치

VP App의 데이터는 **실행하는 Windows 사용자 계정별**로 저장됩니다. 자동 실행·운영에 사용할 계정으로 로그온하여 설정하십시오.

| 위치 | 내용 |
|------|------|
| 설치 폴더 (기본 `C:\Program Files\VP App`) | 프로그램 파일. `.update\` 하위에 웹 업데이트 작업 파일·결과(`result.json`, `updater.log`) |
| `%APPDATA%\db` | 설정·파일 목록·재생목록·타임라인·라이브 소스 DB (`status.db`, `files.db`, `folders.db`, `playlists.db`, `timelines.db`, `sources.db`) |
| `%APPDATA%\vp_app2\logs` | 애플리케이션 로그 `application-YYYY-MM-DD.log` (일 단위 회전, 지난 로그는 압축, 30일 보관) |
| `%APPDATA%\vp_app2\tmp` | 임시 파일 |
| `%USERPROFILE%\media` | 업로드한 미디어 파일 |

`%APPDATA%`는 일반적으로 `C:\Users\<사용자>\AppData\Roaming`입니다.

PC 교체나 백업 시에는 앱을 종료한 뒤 `%APPDATA%\db`와 `%USERPROFILE%\media`를 함께 백업하십시오.

## 4. 네트워크 포트와 방화벽

### 4.1 포트 표

| 포트 | 프로토콜 | 방향 | 용도 | 필요한 경우 |
|------|----------|------|------|-------------|
| 3000 | TCP | 수신 | 웹 UI·REST API·실시간 상태(Socket.IO). 멀티 PC 마스터가 슬레이브를 관리할 때도 사용 | 항상 (원격 접속, 멀티 PC) |
| 15000 | TCP | 수신 | 간단 텍스트 명령 제어 포트 | 외부 제어기 연동 |
| 15001 | TCP | 수신 | JSON 명령 제어 포트 | 외부 제어기 연동 |
| 15002 | UDP | 수신 (슬레이브) | 멀티 PC 재생 트리거 (마스터 → 슬레이브 유니캐스트) | 멀티 PC 동기 |
| 15003 | UDP 멀티캐스트 `239.255.42.100` | 송수신 | 멀티 PC 자동 검색(디스커버리) | 멀티 PC 동기 |
| 15004 | UDP | 수신 (마스터) | 소프트웨어 넷클럭 (슬레이브 → 마스터) | 멀티 PC 동기 (넷클럭/자동 모드) |
| 319, 320 | UDP 멀티캐스트 | 송수신 | PTP(IEEE 1588) 클럭 동기 | 멀티 PC 동기 (PTP/자동 모드) |
| 라이브 소스 지정 포트 (RTP 기본 5004) | UDP | 수신 | RTP/UDP 라이브 입력 | 라이브 입력 사용 시 |

참고:

- 재생 엔진과 서버 사이의 내부 제어 연결은 루프백(127.0.0.1)에서만 사용되므로 방화벽 설정이 필요 없습니다.
- 제어 포트 15000/15001이 이미 사용 중이면 VP App은 다음 번호 포트로 자동 재시도합니다. 실제 사용 중인 포트는 로그에서 확인하십시오 ([12. 문제 해결](#12-문제-해결) 참고). 외부 제어기 연동 현장에서는 다른 프로그램이 이 포트를 쓰지 않도록 하십시오.
- 웹 포트와 TCP 제어 포트(단순 형식)는 웹 화면의 **설정 › 일반 › 네트워크**에서 바꿀 수 있으며, 앱을 다시 시작하면 적용됩니다. 시스템 환경 변수 `VP_WEB_PORT`를 지정하면 웹 포트는 그 값이 우선합니다. 포트를 바꾸면 해당 포트에 맞게 방화벽 규칙을 추가하십시오. 멀티 PC 구성에서는 각 PC가 자신의 웹 포트를 검색 정보에 포함해 알리므로 PC마다 달라도 동작합니다. 특별한 이유가 없으면 기본값 3000을 유지하는 것을 권장합니다.
- 멀티 PC 트리거 포트(15002)와 멀티캐스트 주소는 **설정 › 동기화 › 고급**에서 바꿀 수 있지만, 모든 PC가 같은 값을 사용해야 합니다. 기본값 사용을 권장합니다.

### 4.2 설치기가 등록하는 방화벽 규칙

설치 시 `방화벽에서 제어/동기 포트 허용`을 선택하면 다음 인바운드 허용 규칙이 등록됩니다.

| 규칙 이름 | 대상 |
|-----------|------|
| VP App HTTP | TCP 3000 |
| VP App TCP Simple | TCP 15000 |
| VP App TCP JSON | TCP 15001 |
| VP App PTP | UDP 319, 320 |
| VP App Sync | UDP 15002-15004 |
| VP App (Server) | 프로그램 `<설치 폴더>\VPApp.exe` |
| VP App (Player) | 프로그램 `<설치 폴더>\player\vplayer.exe` |
| VP App (PTP Helper) | 프로그램 `<설치 폴더>\player\gst-ptp-helper.exe` |

프로그램 단위 규칙은 모든 네트워크 프로필(도메인/개인/공용)에 적용되며, 첫 실행 시 Windows 방화벽 허용 팝업이 뜨지 않게 합니다. 재생 엔진(`vplayer.exe`) 규칙이 있으므로 RTP/UDP 라이브 입력 수신 포트도 함께 허용됩니다.

### 4.3 수동으로 방화벽 규칙 등록

설치 시 방화벽 작업을 선택하지 않았거나, 보안 정책상 규칙을 직접 관리해야 하는 경우 **관리자 명령 프롬프트**에서 실행합니다. 설치 폴더가 기본값이 아니면 경로를 바꾸십시오.

```bat
netsh advfirewall firewall add rule name="VP App HTTP" dir=in action=allow protocol=TCP localport=3000
netsh advfirewall firewall add rule name="VP App TCP Simple" dir=in action=allow protocol=TCP localport=15000
netsh advfirewall firewall add rule name="VP App TCP JSON" dir=in action=allow protocol=TCP localport=15001
netsh advfirewall firewall add rule name="VP App PTP" dir=in action=allow protocol=UDP localport=319,320
netsh advfirewall firewall add rule name="VP App Sync" dir=in action=allow protocol=UDP localport=15002-15004

netsh advfirewall firewall add rule name="VP App (Server)" dir=in action=allow program="C:\Program Files\VP App\VPApp.exe" enable=yes profile=any
netsh advfirewall firewall add rule name="VP App (Player)" dir=in action=allow program="C:\Program Files\VP App\player\vplayer.exe" enable=yes profile=any
netsh advfirewall firewall add rule name="VP App (PTP Helper)" dir=in action=allow program="C:\Program Files\VP App\player\gst-ptp-helper.exe" enable=yes profile=any
```

RTP/UDP 라이브 입력 포트를 포트 단위로만 허용해야 하는 경우의 예 (포트 5004):

```bat
netsh advfirewall firewall add rule name="VP App Live RTP" dir=in action=allow protocol=UDP localport=5004
```

등록된 규칙 확인 및 삭제:

```bat
netsh advfirewall firewall show rule name="VP App HTTP"
netsh advfirewall firewall delete rule name="VP App HTTP"
```

## 5. 모니터 구성

### 5.1 출력 창과 모니터 지정

출력 창은 **화면 구성** 메뉴의 `출력 창 관리`에서 추가·배치합니다.

- `출력 창 추가`로 화면 창을, `오디오 전용 창 추가 (화면 송출 없음)`로 소리만 내보내는 창을 만듭니다.
- 각 창은 `모니터`, 위치·크기(px), `비율`(레터박스 / 크롭(채움) / 스트레치), `배경색`, `Z 순서`를 가집니다. `너비/높이 0 = 모니터 전체`입니다.
- 새 창을 만들 때 주 모니터가 아닌 모니터가 있으면 그 모니터가 기본 출력 대상으로 선택됩니다 (제어 화면과 출력 화면 분리).
- 모니터 배치도에서 창을 드래그해 이동하고, 우하단 모서리로 크기를 조절할 수 있습니다.
- 현재 배치는 같은 화면에서 프리셋으로 저장·복원할 수 있습니다.

### 5.2 모니터 고정 방식

Windows의 모니터 순번은 부팅 순서, 늦게 켜지는 모니터, 배치 변경 등에 따라 바뀔 수 있습니다. VP App은 이 문제를 피하기 위해 창을 **물리 모니터 고유 식별자**(Windows 디스플레이 장치 경로 기반 키)에 고정하고, 키로 찾지 못하면 **모니터 EDID 일련번호**(같은 일련번호의 모니터가 하나일 때만)로 찾습니다.

- 창에서 모니터를 선택하면 그 시점의 모니터 식별자가 저장됩니다.
- 이후 재부팅이나 연결 순서가 바뀌어도 창은 같은 물리 모니터에 표시됩니다.
- `주 모니터`로 지정한 창은 항상 Windows 주 모니터를 따릅니다.

### 5.3 모니터가 연결되지 않았을 때

- 지정한 모니터가 연결되어 있지 않으면 해당 창은 **숨겨진 상태로 대기**하며, 다른 모니터로 옮겨지지 않습니다. 설정 화면에는 `연결 안 됨`으로 표시됩니다.
- 재생 엔진은 약 2초 간격으로 모니터 구성 변화를 확인하며, 모니터가 연결되면 창이 자동으로 원래 위치에 다시 표시됩니다.

### 5.4 현장 권장 사항

- 모니터·디스플레이 장치를 최종 배선한 상태에서 창을 배치하고 모니터를 선택하십시오.
- 이전 버전에서 업그레이드한 설정은 첫 실행 시의 모니터 순번으로 고정됩니다. 업그레이드 후 창이 엉뚱한 모니터에 표시되면 해당 창의 `모니터`를 다시 선택하십시오.
- 모니터 교체 시 (식별자와 일련번호가 모두 바뀌므로) 해당 창의 모니터를 다시 선택해야 합니다.
- Windows 디스플레이 설정에서 해상도·배율·배치를 먼저 확정한 뒤 VP App 창을 배치하십시오.

## 6. 오디오 장치와 ASIO

### 6.1 전역 출력 장치

**설정 › 오디오 › 오디오 출력 장치**에서 기본 출력 장치를 선택합니다. 목록에는 Windows 오디오 장치와, ASIO 드라이버가 설치된 경우 ASIO 장치가 표시됩니다.

### 6.2 창별 출력 장치와 뮤트

**화면 구성 › 출력 창 관리**의 각 창 `오디오` 항목에서:

- `출력 디바이스`: 이 창의 소리(클립, 라이브 입력, 창 항목 오디오)를 보낼 장치. 기본값은 `전역 디바이스 따름`입니다.
- `창 오디오 전체 뮤트`: 해당 창의 소리를 모두 끕니다.

주의 사항:

- 출력 디바이스를 바꾸면 창이 다시 생성되므로 재생 중인 내용이 멈춥니다. 운영 전에 설정하십시오.
- 지정한 장치가 연결되어 있지 않으면 전역 장치로 출력됩니다.
- **ASIO 장치는 동시에 1개만** 사용할 수 있습니다. 전역 장치와 창별 장치를 통틀어 두 번째 ASIO 장치를 지정하면 거부됩니다 (창에 지정한 경우 그 창은 전역 장치로 출력).
- 채널별 오디오 지연(스피커 동기 보정)은 전역 출력 장치에만 적용됩니다. 마스터 볼륨은 모든 출력에 적용됩니다.

## 7. 멀티 PC 동기 구성

여러 대의 VP App PC가 같은 시각에 재생을 시작하도록 묶는 기능입니다. 한 대를 **Master(주)**, 나머지를 **Slave(종)**로 지정합니다.

### 7.1 역할

| 역할 (설정 화면 표기) | 동작 |
|------|------|
| 단독 (동기 안 함) | 기본값. 검색·동기 기능이 완전히 꺼집니다. |
| Master (주) | 네트워크의 슬레이브를 자동 검색하고, 쇼(재생 구성)를 지휘합니다. 메뉴에 `플레이어`(마스터 콘솔)가 추가됩니다. |
| Slave (종) | 약 3초마다 자신을 네트워크에 알리고, 마스터의 재생 지시를 받습니다. |

마스터는 슬레이브의 응답이 약 10초간 없으면 `오프라인`으로 표시합니다 (목록에서 삭제하지는 않음).

### 7.2 클럭 소스

**설정 › 동기화 › 클럭 소스**에서 선택합니다.

| 항목 | 설명 |
|------|------|
| 자동 (하드웨어 PTP 우선, 없으면 소프트웨어) | 기본값. 먼저 PTP로 동기를 시도하고, 동기되지 않으면 VP 소프트웨어 넷클럭으로 전환합니다. |
| 하드웨어 PTP (AES67/Dante) | PTP(IEEE 1588)를 사용합니다. 네트워크에 AES67/Dante 등 PTP 그랜드마스터가 있으면 그 클럭을 따르고, 없으면 VP PC 간에 PTP 클럭을 맞춥니다. |
| 소프트웨어 넷클럭 (VP 마스터) | 마스터 PC가 클럭 기준이 되고, 슬레이브가 마스터의 UDP 15004로 접속해 시각을 맞춥니다. |

동작 세부:

- 쇼 재생 시 마스터가 선택된 클럭 방식을 슬레이브에도 적용합니다. 넷클럭 사용 시 마스터 IP는 자동으로 슬레이브에 전달됩니다.
- 동기 중에는 5초마다 클럭 상태를 점검해, 동기가 풀리면 자동으로 다시 맞춥니다. `자동` 모드에서 PTP 미동기가 약 15초 이상 계속되면 넷클럭으로 전환합니다.
- PTP 도메인 기본값은 0입니다. 기존 AES67/Dante 네트워크와 함께 쓸 때는 그 네트워크의 PTP 도메인과 맞추십시오 (**설정 › 동기화 › 고급 › PTP 도메인**).

### 7.3 네트워크 요구 사항

- **모든 PC는 같은 서브넷(같은 L2 네트워크)에 있어야 합니다.** 자동 검색은 멀티캐스트 `239.255.42.100:15003`을 사용합니다.
- 스위치가 멀티캐스트를 차단하지 않아야 합니다. IGMP 스누핑이 켜진 관리형 스위치에서는 IGMP 쿼리어(Querier)가 네트워크에 있어야 멀티캐스트 그룹이 유지됩니다. 쿼리어가 없으면 일정 시간 후 검색·PTP 패킷이 끊길 수 있습니다.
- PTP 모드는 표준 PTP 멀티캐스트(UDP 319/320)를 사용합니다. Wi-Fi, 무선 브리지, VPN 구간은 동기 정확도가 크게 떨어지므로 유선 LAN을 사용하십시오.
- 마스터는 슬레이브의 웹 포트(기본 TCP 3000)로 접속해 상태를 조회하고 파일·재생목록을 관리하므로, **슬레이브의 TCP 3000이 마스터에서 접근 가능**해야 합니다.
- 각 PC는 자신의 IPv4 주소를 하나 골라 알립니다(링크 로컬 169.254.x.x 주소는 후순위). 여러 네트워크 어댑터가 있는 PC는 동기용 LAN 외의 사용하지 않는 어댑터(가상 어댑터, 미사용 NIC 등)를 비활성화하는 것을 권장합니다.
- 각 PC에 고정 IP를 지정하는 것을 권장합니다.
- 방화벽: 모든 PC에 [4.2](#42-설치기가-등록하는-방화벽-규칙)의 규칙이 필요합니다 (UDP 319/320, 15002-15004, TCP 3000).

### 7.4 구성 순서

1. 모든 PC에 VP App을 설치하고 방화벽 규칙을 등록합니다.
2. 각 PC에 재생할 미디어와 재생목록을 준비합니다. 마스터 콘솔의 `관리` 기능으로 마스터에서 슬레이브의 파일·재생목록을 원격으로 관리할 수도 있습니다.
   - **미러 모드**를 쓸 경우 모든 PC에 같은 콘텐츠와 **같은 재생목록 ID**의 재생목록을 만드십시오. 미러 재생목록 선택지는 첫 번째 온라인 플레이어의 재생목록을 기준으로 표시되며, 각 PC는 같은 ID의 재생목록을 재생합니다.
3. 각 슬레이브 PC에서 **설정 › 동기화**를 열고 `역할`을 `Slave (종)`로 선택한 뒤 `적용`(저장 버튼)을 누릅니다.
4. 마스터 PC에서 `역할`을 `Master (주)`로, `클럭 소스`를 선택한 뒤 `적용`을 누릅니다. 메뉴에 `플레이어`가 나타납니다.
5. 마스터의 **플레이어** 메뉴를 엽니다. 슬레이브가 `온라인`으로 표시되는지 확인합니다. 보이지 않으면 `새로고침`을 누릅니다.
6. `쇼` 영역에서 `모드`를 고릅니다.
   - `미러 (동일 콘텐츠, 완전 락스텝)`: `미러 재생목록`을 선택합니다. 마스터 포함 모든 PC가 같은 재생목록을 재생하며, 장면 전환도 마스터가 지휘합니다.
   - `분산 (플레이어별 콘텐츠, 시작 동기)`: `배정`에서 플레이어마다 재생목록을 지정합니다. 시작 시각만 맞추고 이후 전환은 각 PC가 스스로 진행합니다.
7. 필요하면 `PTP 도메인`, `리드 타임`(기본 1000ms: 재생 지시 후 실제 시작까지의 여유 시간)을 조정하고 `쇼 저장`을 누릅니다.
8. `쇼 재생`으로 동기 재생을 시작하고, `쇼 정지`로 모든 PC를 정지합니다.

### 7.5 동기 확인

- **설정 › 동기화** 상단의 `PTP` 배지: `동기됨` / `동기 대기` / `비활성`.
- 마스터 콘솔의 플레이어 목록: 각 플레이어의 `온라인`/`오프라인`, PTP 상태(`동기됨`/`대기`/`꺼짐`), `재생 중` 재생목록.
- 마스터 콘솔의 `동기 진단 (클럭 오차)`: `측정`을 누르거나 `자동`을 켜면 플레이어별 `마스터 대비 오차`와 `왕복시간`이 표시됩니다. 모든 플레이어가 `동기` 상태이고 오차가 작게 유지되는지 확인합니다.
- 쇼 재생 시 클럭 동기가 제한 시간 안에 완료되지 않으면 동기가 덜 된 상태로 재생을 시작합니다. 이 경우 로그에 `clock not fully synced within timeout` 경고가 남습니다.

## 8. 라이브 입력 네트워크 요구 사항

**라이브 소스** 메뉴에서 네트워크 영상 입력을 등록하고, 출력 창에 귀속시켜 재생합니다. 라이브 소스는 재생목록과 별개로 창에 계속 표시되는 레이어입니다.

| 프로토콜 (화면 표기) | 설정 항목 | 네트워크 |
|------|------|------|
| RTSP (카메라/인코더) | `주소(URL)` 예: `rtsp://192.168.0.10:554/stream1` | VP App이 카메라/인코더에 접속 |
| RTP | `멀티캐스트 주소 (선택)`, `포트`(기본 5004), `코덱`(기본 자동), `페이로드 타입`(기본 96), `클럭 레이트`(기본 90000) | 송출기가 VP App PC로(또는 멀티캐스트 그룹으로) 송출, VP App PC의 UDP 포트 수신 |
| UDP (원본 MPEG-TS) | `멀티캐스트 주소 (선택)`, `포트` | RTP 헤더 없는 MPEG-TS를 UDP로 수신 |
| SRT (저지연) | `주소(URL)` 예: `srt://192.168.0.10:9000?mode=caller` | caller 모드는 VP App이 송출기에 접속. listener 모드로 쓰는 경우 해당 UDP 포트 수신 허용 필요 |
| NDI | `NDI 소스 이름` 또는 `주소 (ip:port, 선택)` | NDI 런타임 별도 설치 필요 |

공통 항목: `버퍼 지연(ms)`(기본 200), `오디오 수신`.

현장 참고:

- **VLC 등에서 RTP로 송출하면 대부분 MPEG-TS over RTP(페이로드 타입 33)입니다.** 이 경우 `코덱`을 `MP2T`, `페이로드 타입`을 `33`으로 지정하십시오. RTP 헤더 없이 MPEG-TS를 보내는 송출기는 `UDP (원본 MPEG-TS)`를 사용합니다.
- 멀티캐스트 입력은 VP App PC와 송출기가 같은 네트워크에 있어야 하며, 스위치의 IGMP 설정(쿼리어 존재)을 확인하십시오.
- H.264/H.265 스트림은 송출기에서 SPS/PPS(시퀀스 헤더)를 주기적으로 반복하도록 설정해야 중간 접속 시에도 디코딩이 시작됩니다.
- 출력 합성 해상도는 1920×1080입니다. 라이브 입력을 4K로 보내도 화질 이득은 없고 대역폭·패킷 손실만 늘어나므로 1080p 송출을 권장합니다.
- 입력이 끊기거나 약 8초간 데이터가 들어오지 않으면 자동으로 재연결을 시도합니다. 연결 상태는 `연결 중…`, `재생 중`, `재연결 중…`, `오류`로 표시되며, 수동 `재연결` 버튼도 있습니다.
- 방화벽: 설치기의 `VP App (Player)` 프로그램 규칙이 있으면 RTP/UDP 수신 포트가 허용됩니다. 포트 단위로 관리하는 경우 [4.3](#43-수동으로-방화벽-규칙-등록)의 예를 참고하십시오.

## 9. 자동 실행과 무인 운영

### 9.1 자동 실행

- **설정 › 일반 › 시작 › 시작 시 자동 실행**을 켜면, 현재 사용자 계정의 Windows 로그온 시 VP App이 자동 실행됩니다. 관리자 권한은 필요 없습니다.
- 등록 위치: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, 값 이름 `VP App`.
- 자동 실행은 **해당 사용자가 로그온해야** 동작합니다. 무인 설치에서는 운영 계정의 Windows 자동 로그온을 설정하십시오.
- 같은 PC에서 VP App이 이미 실행 중이면(웹 포트 사용 중) 두 번째 실행은 즉시 종료되므로, 중복 실행 걱정은 없습니다.

### 9.2 부팅 시 자동 재생

**설정 › 일반 › 시작**에서 `부팅 시 재생`을 켜고 `재생목록 ID`를 지정하면, 앱 시작 시 해당 재생목록을 자동으로 재생합니다.

### 9.3 Windows 권장 설정 (무인 운영)

VP App 자체 설정이 아닌 Windows 측 권장 사항입니다.

- 전원 옵션: 고성능 계획 사용, **절전/최대 절전 모드 사용 안 함**, **디스플레이 끄기 사용 안 함**.
- 화면 보호기 사용 안 함, 잠금 화면 시간 제한 해제.
- Windows 업데이트의 자동 재시작 시간을 운영 시간 외로 설정(활성 시간 지정).
- 네트워크 어댑터 전원 관리에서 "전원 절약을 위해 컴퓨터가 이 장치를 끌 수 있음" 해제 (멀티 PC 동기·원격 제어 안정성).
- USB 선택적 절전 해제 (USB 오디오 인터페이스 사용 시).
- 알림·팝업이 출력 화면을 가리지 않도록 집중 지원(방해 금지) 설정.

### 9.4 운영 중 주의

- 재생 엔진 프로세스(`vplayer.exe`)가 종료되면 VP App 전체가 종료됩니다. 이 경우 바탕 화면 바로 가기로 다시 실행하거나 재로그온하십시오. 원인은 로그에서 확인합니다.
- 출력 창 배치·오디오 장치 변경은 재생 중인 내용을 멈출 수 있으므로 운영 시간 외에 하십시오.

## 10. 소프트웨어 업데이트

업데이트 방법은 두 가지입니다.

| 방법 | 파일 | 사용 시기 |
|------|------|-----------|
| 웹 업데이트 | `VP-App-Update-<버전>.vpu` | 일반적인 버전 업데이트. 설치 파일 없이 웹 UI에서 진행 |
| 설치 파일 재설치 | `VP-App-Setup-<버전>.exe` | 신규 설치, 웹 업데이트가 불가한 경우, 설치 구성(방화벽·바로 가기·권한 등) 변경이 필요한 경우 |

### 10.1 웹 업데이트 절차

1. **설정 › 시스템 › 소프트웨어 업데이트**에서 현재 버전을 확인합니다.
2. `업데이트 파일 선택`으로 `.vpu` 파일을 업로드합니다. 파일은 이 제품용으로 암호화·서명되어 있으며, 업로드 후 복호화·검증을 거칩니다.
3. 확인 창에서 버전 변경(v현재 → v새 버전)을 확인하고 진행합니다. **재생이 중단되고 앱이 재시작됩니다.**
4. 업데이트가 끝나면 페이지에 `v<버전> 으로 업데이트되었습니다.`가 표시됩니다.

동작 특성:

- 새 버전이 정상 기동하지 않으면 자동으로 이전 버전으로 되돌립니다 (`업데이트에 실패해 이전 버전으로 되돌렸습니다`).
- 업데이트 결과와 진행 로그는 설치 폴더의 `.update\result.json`, `.update\updater.log`에 남습니다.
- 웹 업데이트는 PC마다 개별로 진행합니다. 멀티 PC 구성에서는 모든 PC를 같은 버전으로 맞추십시오.
- 설정·재생목록·미디어 등 사용자 데이터는 영향받지 않습니다.

### 10.2 설치 파일로 재설치가 필요한 경우

- `설치 폴더에 쓰기 권한이 없습니다 — 최신 설치 파일로 한 번 재설치하세요.`가 표시될 때 (설치 폴더 쓰기 권한을 부여하지 않던 구버전 설치본)
- `업데이트 파일을 복호화할 수 없습니다`가 표시되고, 파일 손상이 아닌 것으로 확인된 경우 (현재 설치본과 호환되지 않는 업데이트 파일)
- 웹 업데이트 대상에 포함되지 않는 서버 실행 파일(`VPApp.exe`) 자체를 교체해야 하는 릴리스

## 11. 설치 후 점검 체크리스트

**기본**

- [ ] 운영할 Windows 계정으로 로그온해 설치·설정했다
- [ ] 같은 PC에서 `http://localhost:3000` 접속이 된다
- [ ] 다른 PC/태블릿에서 `http://<IP>:3000` 접속이 된다 (원격 제어 사용 시)
- [ ] **설정 › 재생 › 하드웨어 가속**이 `지원됨 (GPU 가속)`이다 (GPU 사용 시)
- [ ] Windows 절전·디스플레이 끄기·화면 보호기가 꺼져 있다

**출력**

- [ ] **화면 구성 › 출력 창 관리**에서 각 창이 올바른 모니터에 지정되어 있고 `연결 안 됨` 표시가 없다
- [ ] PC 재부팅 후에도 창이 같은 모니터에 표시된다
- [ ] 화면 구성을 프리셋으로 저장했다
- [ ] 전역/창별 오디오 출력 장치에서 소리가 나온다. ASIO는 1개만 사용한다

**시작**

- [ ] `시작 시 자동 실행`이 켜져 있다
- [ ] 필요 시 `부팅 시 재생`과 `재생목록 ID`가 설정되어 있다
- [ ] Windows 자동 로그온 후 재부팅 시 자동으로 재생이 시작된다

**외부 제어 (사용 시)**

- [ ] 제어기에서 TCP 15000(텍스트) 또는 15001(JSON)로 접속·명령이 된다 ([AMX/TCP 연동 매뉴얼](TCP_PROTOCOL.md))

**멀티 PC (사용 시)**

- [ ] 모든 PC가 같은 서브넷, 같은 버전이다
- [ ] 마스터의 **플레이어** 메뉴에 모든 슬레이브가 `온라인`으로 표시된다
- [ ] `동기 진단`에서 모든 플레이어가 동기 상태이다
- [ ] `쇼 재생` / `쇼 정지`가 모든 PC에서 동작한다
- [ ] 마스터와 슬레이브를 각각 재부팅한 후에도 검색과 동기 재생이 복구된다

**라이브 입력 (사용 시)**

- [ ] 소스 상태가 `재생 중`이 된다
- [ ] 송출기를 껐다 켰을 때 자동으로 재연결된다

## 12. 문제 해결

### 12.1 로그 확인

로그 위치: `%APPDATA%\vp_app2\logs\application-YYYY-MM-DD.log`

탐색기 주소창에 `%APPDATA%\vp_app2\logs`를 입력하면 바로 열 수 있습니다. 문제를 문의할 때는 해당 날짜의 로그 파일을 함께 전달하십시오.

주요 로그 문구:

| 로그 문구 | 의미 |
|-----------|------|
| `Web server running at http://localhost:<포트>` | 웹 서버 정상 시작 |
| `Port <포트> in use — another instance is already running. Exiting.` | 웹 포트가 이미 사용 중 (다른 VP App 인스턴스 또는 다른 프로그램) |
| `Simple TCP server listening on port <포트>` / `JSON TCP ...` | 제어 포트 실제 번호 |
| `... port <포트> is already in use. Trying alternative port...` | 제어 포트 충돌로 다음 번호로 재시도 |
| `discovery started (role=...) on 239.255.42.100:15003` | 멀티 PC 검색 시작 |
| `discovery membership failed` | 멀티캐스트 그룹 가입 실패 (네트워크 어댑터 문제) |
| `clock health: unsynced ...` | 클럭 미동기, 자동 복구 시도 중 |
| `falling back to net clock` | 자동 모드에서 PTP 실패로 넷클럭 전환 |

### 12.2 웹 UI에 접속할 수 없음

- 같은 PC에서 `http://localhost:3000`은 되는데 다른 PC에서 안 되면: 방화벽 규칙(`VP App HTTP`, `VP App (Server)`) 확인, 네트워크 프로필·보안 소프트웨어 확인.
- 같은 PC에서도 안 되면: 작업 관리자에서 `VPApp.exe`가 실행 중인지 확인합니다. 로그에 포트 사용 중 메시지가 있으면 다음 명령으로 포트를 점유한 프로세스를 찾습니다.

```bat
netstat -ano | findstr :3000
tasklist /FI "PID eq <PID>"
```

### 12.3 외부 제어기가 접속되지 않음

- 로그에서 제어 포트가 15000/15001에서 다른 번호로 바뀌지 않았는지 확인합니다. 바뀌었다면 포트를 점유한 프로그램을 정리하고 VP App을 재시작합니다.

```bat
netstat -ano | findstr ":15000 :15001"
```

- 방화벽 규칙 `VP App TCP Simple`, `VP App TCP JSON`을 확인합니다.

### 12.4 마스터에서 슬레이브가 보이지 않음

- 슬레이브의 역할이 `Slave (종)`로 저장되었는지 확인합니다. `단독`이면 검색에 응답하지 않습니다.
- 두 PC가 같은 서브넷인지 확인합니다 (라우터를 넘는 구성은 지원 대상이 아닙니다).
- UDP 15003 방화벽 허용 여부를 확인합니다 (`VP App Sync` 규칙).
- 스위치의 IGMP 스누핑/멀티캐스트 필터링 설정, IGMP 쿼리어 존재 여부를 확인합니다. 처음에는 보이다가 몇 분 뒤 `오프라인`이 된다면 쿼리어 부재를 의심합니다.
- 여러 네트워크 어댑터가 있는 PC는 사용하지 않는 어댑터를 비활성화한 뒤 VP App을 재시작합니다.
- 마스터의 **플레이어** 화면에서 `새로고침`을 누릅니다.

### 12.5 슬레이브는 보이지만 관리·재생이 안 됨

- 마스터에서 `http://<슬레이브 IP>:3000`에 브라우저로 접속되는지 확인합니다 (슬레이브 TCP 3000 방화벽).
- 슬레이브의 UDP 15002(재생 트리거) 허용 여부를 확인합니다.
- 미러 모드라면 슬레이브에 같은 재생목록 ID의 재생목록이 있는지 확인합니다.
- 모든 PC의 **설정 › 동기화 › 고급** 값(멀티캐스트 주소, 포트)이 같은지 확인합니다.

### 12.6 PTP가 `동기 대기`에서 넘어가지 않음

- UDP 319/320 방화벽 허용 및 `VP App (PTP Helper)` 프로그램 규칙을 확인합니다.
- 스위치에서 PTP 멀티캐스트가 차단되지 않는지 확인합니다.
- 기존 AES67/Dante 네트워크와 함께 쓰는 경우 PTP 도메인이 일치하는지 확인합니다.
- 네트워크 환경상 PTP가 어려우면 `클럭 소스`를 `소프트웨어 넷클럭 (VP 마스터)`로 바꾸고, 마스터의 UDP 15004 수신이 허용되어 있는지 확인합니다. `자동` 모드는 PTP 실패 시 넷클럭으로 자동 전환합니다.

### 12.7 출력 창이 표시되지 않음

- **화면 구성 › 출력 창 관리**에서 해당 창의 모니터가 `연결 안 됨`이면 모니터 연결·전원·입력 소스를 확인합니다. 연결되면 자동으로 표시됩니다.
- 모니터를 교체했다면 창의 `모니터`를 다시 선택합니다.

### 12.8 라이브 입력이 `재연결 중…`을 반복함

- 패킷이 도착하지 않는 경우: 송출 대상 IP/포트, 멀티캐스트 그룹, 방화벽(UDP 수신), 스위치 IGMP 설정을 확인합니다.
- 패킷은 오지만 디코딩되지 않는 경우: RTP 송출이 MPEG-TS(페이로드 33)인지 확인해 `코덱`/`페이로드 타입`을 맞추고, 송출기에서 SPS/PPS 반복 전송을 켭니다.
- 송출 해상도를 1080p로 낮춰 대역폭을 줄입니다.

### 12.9 소리가 나지 않음

- 전역 장치와 창별 `출력 디바이스` 설정을 확인합니다. 창별 장치가 연결되어 있지 않으면 전역 장치로 출력됩니다.
- `창 오디오 전체 뮤트`가 켜져 있지 않은지 확인합니다.
- ASIO 장치를 두 개 이상 지정하지 않았는지 확인합니다 (동시에 1개만 사용 가능).

### 12.10 웹 업데이트 실패

| 메시지 | 조치 |
|--------|------|
| 설치 폴더에 쓰기 권한이 없습니다 | 최신 설치 파일로 한 번 재설치 |
| 업데이트 파일을 복호화할 수 없습니다 | 파일을 다시 받아 시도. 계속되면 설치 파일로 재설치 |
| VP App 업데이트 파일(.vpu)이 아니거나 손상되었습니다 | 올바른 `.vpu` 파일인지 확인 |
| 다른 업데이트가 진행 중입니다 | 진행 중인 업데이트가 끝난 뒤 다시 시도 |
| 앱 재시작 확인 시간이 초과되었습니다 | 잠시 후 페이지 새로고침. 설치 폴더 `.update\updater.log` 확인 |
